Stream processing patterns in Flink SQL

Watch records, state and watermarks move through the job graph of each basic Flink SQL pattern. The examples follow a chain of pizza shops, and the orders that stream in from every store.

    How to read the diagrams

    Every pattern is a Flink job: a Kafka source on the left, a Kafka sink on the right, and the operators the planner chose in between. Press Play, or step through one record at a time with ← and →.

    Stream types
    append-only only inserts. Each record is a new fact.
    upsert inserts, updates and deletes, by key. An update replaces the row with the same key.
    retract every update is sent as a pair: retract the old row, then add the new one.
    Row kinds
    +I insert −U retract the old version +U the new version −D delete
    Watermarks
    WM 12:00:04 travels with the data and says no record older than this time should follow. Operators that wait for time use it to know when to act.
    Operators
    stateless stateful keeps keyed state, shown underneath it. added by the planner isn't in your SQL, but the planner needs it to produce correct results. Calcs that only drop columns, or set up a time attribute, are left out.

    Job graphs and changelog modes are checked with EXPLAIN CHANGELOG_MODE on Apache Flink 2.3. The animations simplify how Flink schedules work, but not what each operator does.
